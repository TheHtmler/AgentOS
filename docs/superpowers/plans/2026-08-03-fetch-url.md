# fetch_url Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register a `fetch_url` tool with Firecrawl→local failover, SSRF guards, truncate+outline payload, and `run_events` summaries matching `web_search`.

**Architecture:** Parallel package `agent_api/tools/fetch/` mirroring `tools/search/`. URL guard runs before any outbound call; `FetchRouter` tries providers in `FETCH_PROVIDER_ORDER`; tool JSON returns `{provider,url,title,outline,text,truncated,total_chars}`.

**Tech Stack:** FastAPI, Pydantic AI, httpx, trafilatura (local extract), Firecrawl HTTP scrape API, pytest.

## Global Constraints

- Tool name exactly `fetch_url`; secrets only in Agent API env.
- Public `http`/`https` only; block loopback/private/link-local/metadata targets; re-validate redirects.
- Default max body chars `10000`; no Artifact/`read_artifact`/LLM summarize in this slice.
- CI mocks Firecrawl; no real Key required in tests.
- Reuse `AgentDeps` + `run_events` tool summary pattern from `web_search`.
