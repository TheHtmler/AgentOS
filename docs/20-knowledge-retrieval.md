## 设计约束

知识库原件与用户附件分开，只有 Ops 可以访问原件。导入保留原件、内容摘要、
解析版本、逐页质量及阶段进度。审核状态与导入质量独立，失败或待复核的新版
不得覆盖可用旧版。向量不足可保留关键词检索，但必须显示降级。

有效向量必须为有限数值的非零数组，且模型、维度和检索文本版本匹配。
JSON null、未知模型和旧版本不计入有效向量。查询生成向量与文档具备向量
分别记录。补建从现存切片进行，不要求重新上传原件。

初期保留 PostgreSQL JSONB 向量，以流式分批遍历全部授权候选替代任意前
200 条截断；候选排名独立融合，标签只在有正文或向量相关性时辅助排序。
不新增常驻服务。后续是否采用数据库向量索引或重排由规模和评测决定。

## 验收

测试必须连接独立的 `_test` 数据库，启动前设置连接，禁止回落业务库。
检索测试覆盖超过 200 切片、病种标签干扰、未知模型、无效向量、口语与
无答案问题。真实场景分别记录检索调用、正确证据进入前五、答案引用和耗时。
旧知识先备份盘点；有完整原文则重切块，有可靠正文则补向量，否则重新上传。
不得以人工整理种子评测通过替代真实文件验收。

## 运维步骤

后端工作目录为 `services/agent-api`。

```bash
uv run python scripts/prepare_test_database.py
uv run pytest -q
uv run python scripts/knowledge_audit.py ../../data/backups/knowledge-before.json
uv run python scripts/evaluate_knowledge.py eval/knowledge-retrieval.json ../../data/knowledge-eval.json
uv run python scripts/knowledge_acceptance.py
```

`prepare_test_database.py` 仅创建/升级名称以 `_test` 结尾的独立库，不创建 Docker
服务。pytest 根 conftest 在应用引擎初始化前替换连接，数据库用例每次清理独立库并
装载无凭据的测试 Provider；用户附件与公共资料归档也使用临时目录。不要并发运行
多个 pytest 进程共享同一个测试库。纯函数测试无需数据库连接。

`knowledge_acceptance.py` 使用实际配置的视觉和 embedding 端点，有真实 API 调用费用。
它生成一个受控 PDF，走 Ops HTTP 路由完成原件归档、转录、检索与向量重建，最终删除
自己创建的临时知识库；不启动定时调度器，不使用用户病例。

`repair_knowledge.py BACKUP` 默认只打印迁移清单，`--apply` 才执行。此工具针对本次
已识别的旧摘要和测试残留，未知文件保持待人工处理。原件在 `KNOWLEDGE_SOURCE_ROOT`
按 SHA-256 归档，权限 0600；成功页缓存包含模型、端点和解析提示版本，失败页重试
不会重复调用已成功页面。文档删除后暂保留归档，备份时需同时备份该目录。

向量配置改变时同时更新 `BACKGROUND_EMBEDDING_MODEL` 和
`KNOWLEDGE_EMBEDDING_DIMENSIONS`，从文档详情执行重建向量。标题改变后已有向量被标记
过期，因为标题属于检索文本。重新解析与重试始终使用已归档原件或解析检查点。
缺失页整次失败；文本层回退进入待复核；失败新版不得替换可用旧版。

## 本次数据处理与结果

2026-09-06 备份了 13 篇文档、41 个切片、821 个快照，文件在部署工作区
`data/backups/knowledge-20260906-before.json`，不进入 Git。
保留 4 篇带来源的教育摘要并生成 32 个有效的 bge-m3 / 1024 维 / context-v2 向量；
9 篇测试残留下架，未物理删除。没有从现存文档或快照中找到用户旧上传文件原件，
完整指南/论文需要重新上传。这是资料缺失，不能靠重新向量化恢复。

受控单页 PDF 的真实视觉、向量、原件下载及重建验收通过。7 条现存摘要查询用例
在新检索器无向量和补齐向量后均通过，英文生长随访相关结果从第 3 位到第 1 位；
这不是完整真实资料集的准确率。真实遗传代谢 Provider 的首轮与追问均调用检索并引用
来源。全库目前仅 32 个有效切片，部署 PostgreSQL 未提供 vector 扩展；暂不新增
向量服务或重排模型。重新上传真实资料后，应扩充带明确目标片段的评测，再判断索引
和重排收益。
